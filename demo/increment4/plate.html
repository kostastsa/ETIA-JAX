What Tetrad 7.6.5 does in the FCI family

PartWhat Tetrad doesETIA-JAX
Threads (all four)One CI test object is used from parallel threads; χ² and G² are not thread-safe: FCI crashes on 11 of 12 discrete searches, other p-values are corrupted.No threads in the search; the fixtures use a race-free Tetrad (serialized test calls).
R4 orderParallel tasks over a HashSet of DiscriminatingPath objects (identity hash): the order varies between runs.A fixed order; in all 8 such cases the result is one of Tetrad's outputs.
R4 path lengthThe collider path is stored in the opposite order, so only the shortest discriminating paths pass.Default: any length. tetrad_compat: the same as Tetrad.
FCI R0A new greedy search for separating sets, not the FAS sets.Default: FAS sets. tetrad_compat: greedy.
Rule scheduleR4 only if R1–R3 changed a mark in the cycle; R5–R7 (selection bias) applied; R10 never fires (List compared with an Edge).Default: Zhang's R1–R4, R8–R10. tetrad_compat: the same as Tetrad.
Possible-m-sepFCI: the search stays on pairs (x, ·); CFCI: a second variant that tests only x's side.Default: Possible-D-SEP of Spirtes et al. tetrad_compat: both variants.
CFCI sepsetsKeeps its own map, empty at the first R0.tetrad_compat: the same.
