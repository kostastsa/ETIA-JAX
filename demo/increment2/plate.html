Agreement with ETIA agreement.csv

Origin

60 queries per dataset (|Z| = 0…3). A Δp of about 1e-10 or less is the same p-value up to rounding. CMIknn has no p-value in ETIA (fixed threshold on the CMI), so its decision uses the statistic. CMIsymb and GPDC use random null distributions. cci and dg_lrt run in tetrad_compat mode here.

Many queries scale.csv · scale_wide.csv

Test
Measure

30-variable data (cont: n = 1000, disc: n = 2000). Unique queries: all 435 pairs for |Z| = 0 and 2000 random queries for each |Z| = 1, 2, 3, so the result caches of Tetrad and tigramite do not help. Calibration and power calibration.csv

100 replicates (60 for cci) from a GenJAX SCM with Z → X, Z → Y. Size: rejections at α = 0.05 when X ⫫ Y | Z (near 5 % is correct). Power: rejections when X → Y is added.

What the timings show

  • Batched queries are the strength of JAX: one vmap call answers 2000 queries in milliseconds. PC and FCI test many queries of the same |Z| at each level, so increment 3 uses this path.
  • One query per call is not always faster: a JAX call costs about 40 µs on the CPU and 0.4 ms on the GPU. Tetrad's Java FisherZ takes 60–125 µs per query.
  • Slower than ETIA today: cg_lrt, dg_lrt and RegressionCI on mixed data, and the table tests one by one. They have no batched path yet.
  • CMIsymb in ETIA falls back to plain Python (numba cannot compile tigramite's shuffle loop): 29 s per query. The JAX shuffle runs in a vmap.
  • GPDC fits a GP with float64 Cholesky factorizations, which are slow on this GPU; batched it is only a little faster than sklearn.
